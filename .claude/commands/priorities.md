`docs/개발보고서.md`의 "남은 작업" 섹션(P1/P2/P3 전체와 그 안의 하위 조사 결과 목록들, 예:
"목표 달성 악용 가능성 전수 조사 결과", "로직 헛점 전수 분석 결과", "Play 스토어 등록 남은 작업",
"다운로드 전환 최적화(ASO) 준비" 등)을 지금 파일 내용 기준으로 다시 읽어서, 아직 안 끝난 항목
(`[ ]`, `[~]`, 보류/미착수로 표시된 것)만 골라 아래 형식으로 정리해서 보여줘.

정리 규칙:
- 카테고리로 묶어서 보여줄 것 (예: 🏪 출시/스토어, 🐛 코드 버그 백로그, 🎨 UX 확인 필요,
  ⚙️ 인프라/설정, 💤 전면 보류 — 실제 파일 내용에 맞게 카테고리는 유동적으로 조정)
- 각 항목은 원문에 있는 🔴🟡🟢⚪ 등급 표시를 그대로 유지하고, 한두 줄로 짧게 요약(원문 전체를
  복붙하지 말 것 — 핵심만)
- 보류/의도적으로 안 하기로 한 항목은 "⏸️ 보류" 같은 표시로 구분해서 착수 예정 항목과 헷갈리지
  않게 할 것
- 완료된([x]) 항목은 보여주지 말 것 — 이 명령은 "남은 일"만 보기 위한 것
- 세부 요구사항이 아직 안 정해진 항목(owner 확인 필요)은 그 사실을 명시할 것
- 목록 끝에 "다음에 뭐부터 하고 싶은지" 짧게 물어볼 것

주의: 이 파일 자체를 캐시된 답으로 쓰지 말고, 항상 `docs/개발보고서.md`를 다시 읽어서 최신 상태
기준으로 답할 것 — 백로그는 세션마다 항목이 추가/완료되며 계속 바뀐다.
